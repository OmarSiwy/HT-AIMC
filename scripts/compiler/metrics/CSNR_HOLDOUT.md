# Held-out CSNR: is the A10 per-column gain calibration real?

Generated by `scripts/compiler/metrics/csnr_holdout.py`. **Zero new simulation** — every number comes from the four already-simulated 17-converter acceptance logs in `analog/testbenches/out/`.

Labels: **measured** = read off a SPICE run; **derived** = arithmetic on measured values; **projected** = model extrapolation.


## 1. What measured data exists

| pass | tile | cal points (col,window) |
|---|---|---|
| `pass_05_typ_attn_q` | attn | 24 |
| `pass_06_typ_attn_k` | attn | 31 |
| `pass_07_typ_attn_v` | attn | 16 |
| `pass_08_typ_attn_o` | attn | 16 |
| `pass_09_typ_ffn_gate` | **ffn** | **0 — log is empty** |

**87 measured points** over **4 independent passes** (4 different weight tiles, 4 different SmolLM2 tokens), 17 columns x 2 nibble windows each; the cal table logs only `|ideal| >= 8` and non-clamped reads, so 49 of the 136 possible points are missing. The FFN class has **no log data at all** — the 16.7 dB FFN figure came from a separate `tb_csnr.py uncorr` run whose per-column data was not persisted, so **no FFN holdout is possible**.


## 2. In-sample vs held-out (leave-one-pass-out)

Fit on 3 passes, score the held-out 4th, pooled over all 4 folds. Error scored as `round(corrected) - y_exact`.

| corrector | free params | in-sample CSNR | held-out CSNR | circularity gap | held-out rms |
|---|---|---|---|---|---|
| none (uncorrected) | 0 | 19.91 dB | **19.91 dB** | +0.00 dB | 4.46 LSB |
| per-window gain | 2 | 27.29 dB | **26.73 dB** | +0.55 dB | 2.03 LSB |
| per-window gain+offset | 4 | 27.45 dB | **26.73 dB** | +0.72 dB | 2.03 LSB |
| per-window gain(n_banks) | 4 | 30.13 dB | **28.70 dB** | +1.43 dB | 1.62 LSB |
| A10 per-column gain | 87 | 40.75 dB | **26.52 dB** | +14.23 dB | 2.08 LSB |

**The circularity is +14.23 dB.** A10 fits one scalar per data point (`g = measured/ideal` at the column's single operating code), so it has **zero residual degrees of freedom** — the in-sample residual is rounding, not physics. On a pass it has not seen it has nothing to say about a new column and falls back to the window mean.


Two framings of the same gap, both worth stating:

1. **Same estimator, in vs out**: 40.75 -> 26.52 dB, a **14.23 dB** collapse. (This file's in-sample figure is *higher* than the 27.8-30.1 dB reported from the 17-column run because `round(measured/g)` is a kinder model of the correction than the reference-span scaling A10 actually uses — per `tb_tile_mvm._col_gain`, span scaling slides the code along a nonlinear staircase. So 40.75 dB is the *purest* statement of the circularity: fit 87 parameters to 87 points and the residual is rounding.)

2. **Against the reported number**: 27.8-30.1 dB reported in-sample vs **26.52 dB** held out — the reported range is 1.3 to 3.6 dB optimistic.


The decisive line is that A10 held out (26.52 dB) is **below** a 2-parameter per-window gain (26.73 dB). Per-column calibration contributes nothing that generalises.


## 3. Where the optimism comes from

- **Genuine, generalising part.** The gain is strongly *window*-structured: g_lo mean 0.9227, g_hi mean 1.0660 (**measured**). The window is a structural property (lo drives `t_chop = t_q`, hi `16*t_q`), known a priori, so correcting it costs 2 parameters and holds up out of sample. Adding an offset and an `n_banks` slope also generalises.

- **Non-generalising part.** Across the 30 columns logged in **both** windows, `corr(g_lo, g_hi) = -0.272` (**measured**) — *negative*. The per-column deviation from the window mean is not a property of the column; it is per-operating-point coarse-loop INL plus code rounding, exactly what `tb_tile_mvm._col_gain`'s own docstring calls an *irreducible high-|code| coarse-loop INL*.

- Transferring the per-column term to the other window gives **22.85 dB vs 27.72 dB** for the window mean alone (-4.87 dB) — the per-column term actively **hurts** out of sample (**measured**).

- So the answer to *'a per-column scalar has few DOF, maybe it generalises'* is **no, because it is one DOF per observation, not one per column**. A per-column gain would need >= 2 operating points per column to be estimated at all, and this data says the two points disagree.


## 4. Reported-range selection effect

| ensemble | n | Var(y) | MSE | CSNR |
|---|---|---|---|---|
| logged only (`\|ideal\| >= 8`) | 87 | 1946 | 19.85 | 19.91 dB (**measured**) |
| all 17 cols x 2 windows | 136 | 1257 | 13.59 | 19.66 dB (**projected**) |

**Selection bias = +0.25 dB.** Var(y) falls from 1946 to 1257 when the 49 small-|code| columns are put back, and the error does *not* shrink proportionally because it is only partly multiplicative:

- `lo`: err = -0.0982*y +0.728 LSB, residual 1.90 LSB rms (**measured** fit). The additive + residual part survives at small |y|, so small columns are *relatively* worse.

- `hi`: err = +0.0610*y -0.128 LSB, residual 1.25 LSB rms (**measured** fit). The additive + residual part survives at small |y|, so small columns are *relatively* worse.


## 5. The honest number

| quantity | value | label |
|---|---|---|
| A10 as reported (in-sample) | 27.8 - 30.1 dB | **circular** |
| A10 held out (leave-one-pass-out) | 26.52 dB | measured |
| best generalising corrector (per-window gain(n_banks)), held out | 28.70 dB | measured |
| ... over the unrestricted code range | **28.45 dB** | derived |
| pass-bootstrap 90% band | 22.64 .. 30.80 dB | derived (n=4 passes, wide) |
| FFN class | no data | — |

**Best defensible held-out attention CSNR: 28.5 dB (90% band 22.6 .. 30.8 dB).** That is +8.5 dB relative to the uncorrected 19.9 dB and -1.6 dB relative to the circular best case. The correction that survives holdout is worth real dB — it is just far less than A10 advertised, and it comes from the *window*/*n_banks* structure, not from per-column calibration.


## 6. K schedule and tok/s the honest CSNR supports

| scenario | SNR_s attn/ffn | K attn/ffn | avg K | N4/7B tok/s | vs Sohu 62,500 |
|---|---|---|---|---|---|
| assumed specs 34/38 (NEVER measured) | 34.0/38.0 | 3/7 | 6.54 | 114,168 | 1.83x |
| A10 in-sample (CIRCULAR) | 40.7/40.7 | 9/9 | 9.00 | 121,903 | 1.95x |
| held-out, logged range | 28.7/28.7 | 1/1 | 1.00 | 17,915 | 0.29x |
| held-out, full range  <- HONEST | 28.5/28.5 | 1/1 | 1.00 | 17,915 | 0.29x |
| uncorrected 19.9/16.7 (measured) | 19.9/16.7 | 1/1 | 1.00 | 17,915 | 0.29x |

**K = 1, N4/7B = 17,915 tok/s = 0.29x Sohu.** The honest CSNR does *not* change the K schedule versus the uncorrected 19.9 dB number — 28.45 dB is still 2.7 dB short of the 31.11 dB that K=2 needs.


One thing *does* change, and it matters: at 28.45 dB the K=1 cascade delivers 28.42 dB end to end, which **clears the 28 dB target**. At 19.9 dB it did not — `k_for_budget` was returning its floor clamp, i.e. the design was failing its own budget at every K. So the honest reading is *K=1 now genuinely passes*, not *K=1 by default*. The margin is ~0.4 dB, well inside the bootstrap band, so treat it as 'at the edge of passing', not 'passed'.


## 7. dB to close

| milestone | SNR_s needed | gap from 28.5 dB |
|---|---|---|
| meet the 28 dB target at K=1 | 28.00 dB | -0.45 dB |
| K=2 | 31.11 dB | +2.66 dB |
| K=4 | 34.44 dB | +5.99 dB |

Candidate levers (from this session, all still to be verified against this held-out baseline, not against the circular one):

- **beta*gm_in of the OTA loop** — `tb_csnr isolate` attributes the dominant error term (d) to the OTA under multi-bank rail load, ~15 dB dominant. It is the same loop that sets `tau_absorb`, so it buys CSNR *and* conv_time. This is the only lever plausibly worth >10 dB.

- **`VCM_FRAC` 0.5 -> 0.546** (+40% usable swing, **measured**) — +40% signal at fixed noise is +2.9 dB if the error is additive. Section 4 says the residual is only partly additive (the gain term is 9.8% on lo), so expect less than that; it does not scale away a multiplicative gain error.

- **`V_SWING` 0.25 -> 0.5** (sky130-only; feasibility veto at advanced nodes) — doubles C_u, -3 dB on the Pelgrom term only, which is not the dominant term here.


**None of these obviously delivers the -0.5 dB needed just to reach the K=1 target**, let alone the 2.7 dB for K=2. The per-column-gain route is closed: the data says a per-column scalar does not generalise. What is *not* closed is a per-column gain estimated from MORE THAN ONE operating point — but no such data exists yet.


## 8. The SPICE run to queue

This analysis is holdout-limited: 4 passes, 1 token each, 1 operating point per (column, window). To settle whether a per-column gain generalises *at all*, the missing run is:

```
# same tile, DIFFERENT tokens: gives >=2 independent operating points
# per column so a per-column gain can be FITTED on one and SCORED on
# another. scripts/compiler/out/acts/*.npz already holds 9 tokens per tensor.
PYTHONPATH=analog/schematics python3 analog/testbenches/tb_csnr.py \
    uncorr pass_05_typ_attn_q          # + repeat for tokens 1..3
PYTHONPATH=analog/schematics python3 analog/testbenches/tb_csnr.py \
    uncorr pass_09_typ_ffn_gate        # the FFN class has NO data
```

Cost: ~25 min/pass. Four attn tokens + one FFN pass ~ 2 h sequential, and it converts the biggest assumption in the K schedule into a measurement.
